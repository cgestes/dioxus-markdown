# Margin · a Rust Markdown notebook

Margin is a live Markdown notebook built with Dioxus Native and Loro. The desktop sample opens on a field note with an editable title, prose, checkboxes, and a pipe table. The browser mockup also supports two-writer sessions and inline agent proposals.

Both editors use the same table stylesheet. A pine header and fine horizontal rules separate the rows. The first left-aligned column uses the heading serif, descriptions use DM Sans, and right-aligned values use IBM Plex Mono. Columns keep their widths while you type. The browser wraps long descriptions at the same positions in reading and editing. [Table styles](assets/table.css) · [Desktop](mockup/native-table.png) · [Browser](mockup/preview.png) · [Phone](mockup/table-mobile.png)

- Run `cargo run --locked --features native --bin margin`. Click the first letter of *Field notes* or any later ATX heading. At that position, **#** adds a heading level up to six, **Space** accepts the Markdown separator, and **Backspace** removes one level. Removing the last hash makes the line a paragraph. The left gutter shows the prefix while that heading is focused. Up and Down move one visual line at a time through headings, wrapped prose, blank lines and table rows. **Source** exposes the same Loro text and undo history. The desktop sample keeps its session in memory. [Native table preview](mockup/native-table.png)
- Open the self-contained HTML in an ordinary browser. Choose *Before the walk* for inline and checklist boxes, or *Listening walk* for lists and tables. [Browser mockup](mockup/index.html) · [Checkbox preview](mockup/checkbox-edit.png) · [Editing a cell](mockup/markdown-edit.png) · [Inline proposal](mockup/inline-edit.png)

## Test native Live editing

Run `./scripts/test-editor --inspect` to open a fresh native note, or double-click the [macOS inspector launcher](scripts/inspect-editor.command). In an existing Live note, click in the text and press **F8** to toggle the inspector. On keyboards with media keys, use **Fn+F8** and **Fn+F9**. [Inspector preview](mockup/native-inspector.png)

The inspector colors headings, blank lines and prose, outlines table controls and paints the active caret magenta. The header shows the focused field, Markdown line and column, directed UTF-8 byte selection and latest input. The native window title keeps the position visible when the header scrolls away. **Save report** or **F9** writes a local JSON file with the starting and current Markdown, focus, text selection, selected table corners, field and caret rectangles, window scale and the last 48 groups of inputs. A frame can contain several inputs between draws. The launcher writes reports under `target/editor-tests/reports`. F8 in an ordinary app uses the system temporary directory under `margin-reports`. Set `MARGIN_REPORT_DIR` to choose another location.

| Command | What it exercises |
| --- | --- |
| `./scripts/test-editor` | Runs the portable Live workflows and, on macOS, a separate native window keyboard check. Opens a disposable note for the window check. |
| `./scripts/test-editor --headless` | Drives pointer, key-down, key-up and IME events through Dioxus, checks the Loro Markdown and native selection, and inspects rendered caret pixels at 1× and 2×. |
| `./scripts/test-editor --headless --seed 17` | Repeats the same sequence of 60 edits. The reference model checks the Markdown and caret after every input. The standard run uses four seeds. |
| `./scripts/test-editor --mac-window` | Drives arrows, Return, deletion, rectangular selection and forward/backward Tab in a new macOS window. Checks its Markdown, focus and selection after each physical key. Uses a logged-in macOS desktop, Orca’s background window driver and the Swift compiler. |

The runner writes a self-contained [HTML report](target/editor-tests/index.html) with the failed checks first. Expand **Passed checks** to inspect the other screenshots or **Inputs and Markdown** to see how a checkpoint was reached. Each run also has its own directory. A mismatch or an unavailable requested window check returns a nonzero exit status. The native window checks use the observed state before each key as their starting point, so an earlier failure does not change the expected behavior of the next gesture. Interactive F9 reports are observations. Seeded workflows can be replayed by seed.

## Try the Split design

Choose **Split** in either toolbar. For a new native session, run `cargo run --locked --features native --bin margin -- --split`. For the browser, open the standalone HTML and click **Split**, or append `?view=split#walk` to the served URL. [Browser preview](mockup/index.html) · [Browser screenshot](mockup/split-edit.png) · [Native screenshot](mockup/native-split.png)

The left pane contains the full Markdown in one native text field or one CodeMirror editor. Edit heading hashes directly, move through a blank line, or drag from a heading across table pipes and replace the selection. The right pane renders the same note. Clicking a formatted letter positions the source caret. Shift-click extends the selection. A table’s right and bottom margins target the nearest cell. The small **+** buttons append a column or row, and select the new header or cell. A missing cell in a short Markdown row only acquires pipes when you type into it.

The same Rust parser supplies the reading layout and the source range for each displayed run on desktop and in the browser via WebAssembly. The browser converts UTF-8 offsets to CodeMirror’s UTF-16 positions. Both panes share the note and undo history. Split leaves Markdown punctuation visible on the writing side and needs space for both panes. ## Try the editor

- Type Markdown directly. Headings, bold, italic, strikethrough, links, inline and fenced code, and blockquotes have live styling. The opening and closing punctuation hide independently until the caret reaches them. The text keeps its position. Focused headings show their prefix in the left margin. **Source** shows every delimiter.
- In prose and task lists, `[ ]`, `[x]`, and `[X]` occupy a fixed space. A checkbox is visible at rest. When the caret is immediately before it, inside it, or immediately after it, the checkbox reveals its Markdown brackets. Between the brackets, **Space** or **X** toggles once. At the outer edges, typing continues normally. Click a marker to toggle it, or Alt-click to place the caret inside. The footer offers **Edit as text** (F2) inside a marker. **Keep literal** writes a Markdown backslash before the opening bracket.
- Click a letter in a table cell to place the caret there. Double-click a word to select it. Tab and Shift+Tab move horizontally. Enter and Shift+Enter move vertically. Tab at the last cell or Enter in the last row creates the next row. Left and Right cross into neighboring cells at the ends of their text. Up and Down keep the current column and leave the grid at the top or bottom. Ctrl/⌘+Home and End reach the first and last cells. Escape returns to the document. Type a pipe header and its alignment line, then press Enter to start the first data row. **Insert table** adds a two-column Markdown table at the current paragraph. **Source** shows its pipes. In the browser, **Table actions → Edit Markdown pipes** opens the source for one table.
- Hover a grid or focus a cell to reveal its two **+** buttons. The right edge adds a column and the bottom edge adds a row. Clicking beside either button puts the caret in the nearest visible edge cell. A click in the following paragraph places it there. A new row opens in its first cell. A new column opens with its header selected. Paste tab- or newline-separated spreadsheet values into a cell to fill a rectangle and expand the table. One Undo reverses the paste or structural command. Click **Table actions** below the left edge or press **Shift+F10** in a cell to delete a row or column. The menu shows the affected address and opens outside the grid when space permits. **Escape** closes it and restores the cell focus. Undo restores the contents and alignment.
- Drag across cells or click one cell and Shift-click another to select a rectangle. Option/Alt+Shift+Arrow starts a range from the keyboard. Shift+Arrow changes its moving corner. Tab and Shift+Tab cycle inside the selected rectangle, and typing edits the active cell. Copy exports tab-separated values. Delete clears the cells. Pasting one value fills the selection, and larger clipboard blocks are clipped at its edges. **Table actions** can remove all selected rows or columns in one undoable edit. The header and final column are protected. Escape returns to editing one cell. [Table selection](mockup/column-controls.png)
- Select words in a heading, paragraph or cell to open the floating formatting bar. Bold, italic, strikethrough and inline code edit Markdown and preserve your selection. The shortcuts use ⌘ on macOS and Ctrl elsewhere, with B, I, Shift+X and E respectively. [Formatting preview](mockup/formatting.png)
- In a bullet, numbered item, or checklist, Enter continues the list. A new task starts unchecked. Tab nests an item and its children under its previous sibling. Shift+Tab outdents it. Enter on an empty top-level item starts a paragraph. Backspace at the first letter outdents a nested item or removes a top-level list prefix. In the browser, ⌘Enter / Ctrl+Enter toggles a task at the caret.
- Open **Collaborate → Open second editor**. Keep both tabs in the same browser profile and edit the note from each. Local edits appear immediately, shared changes merge, and each editor owns its undo. The mockup uses a same-origin browser channel. Cross-device sessions are a native implementation milestone.
- Select a sentence and choose **Ask inline** or press ⌘J / Ctrl+J. Try **Make a checklist**, ask a question, or type `Replace with:` followed by your own Markdown. Review the original and proposed text, then **Apply edit** or **Discard**. The local demo uses deterministic replies. Accepted edits can be undone in one step.
- Use **Notebook +** to start a note. The browser stores changes locally. **Export .md** downloads the Markdown of the open note.

The browser stores Loro updates in IndexedDB and sends updates and cursor presence between tabs. Its one-time importer reads saved notes from the earlier browser study. The HTML includes the Rust checkbox module, Loro, fonts, scripts, icons, and distribution notices.

For a consistent origin across tabs, run `python3 -m http.server 4327 --bind 127.0.0.1 --directory mockup` and open the loopback preview. To rebuild, install the Rust target with `rustup target add wasm32-unknown-unknown`, then run `npm ci` and `npm run build` inside `mockup`. Run `npm test` there for browser editing regressions and `cargo test --locked --features native` at the repository root for the Rust model and Dioxus Native keyboard tests. [Open Before the walk](http://127.0.0.1:4327/index.html#departure)

In a local Orca browser run with two Loro editors connected, 20 keystrokes in the middle of a 100-row, eight-column table kept the same focused cell input and its vertical position. Time from `beforeinput` through the cell update and a synchronous layout read was 4.9 ms at the median and 8.0 ms at the 95th percentile. Concurrent same-cell typing, adding and undoing a column, and rectangular paste also converged in both tabs.

## How a checkbox edit works

1. **Find the source range.** The Rust parser recognizes GFM task markers and scans ordinary Markdown text for the same three-character tokens. This second rule is a notebook extension. Links, code, and escaped brackets keep their Markdown meaning. The browser runs this same parser as WebAssembly and caches the result for each document revision. [Rust parser and command](src/checkbox.rs) · [GFM task-list syntax](https://github.github.com/gfm/#task-list-items-extension-)
2. **Consume the input once.** Both caret positions inside the brackets and a selection of just the middle character are eligible. Space, x, and X request the opposite value. Key repeat and other text edits inside a structured marker leave it alone. Arrow keys navigate normally. A selection spanning a bracket uses ordinary text semantics. Literal editing is local to the view. A saved `\[x]` travels with the document. [Native input handling](src/native/writing.rs) · [Browser adapter](mockup/src/checkbox.js)
3. **Commit to Loro.** Each note has a `LoroText` named `markdown`. A structured toggle applies the Boolean `markdown.checked` attribute to the existing middle character with expansion disabled. Two disconnected peers checking the same box target the same character. Ordinary source edits splice text. Reading Source or exporting projects the attribute onto that one ASCII character, producing plain `[x]` or `[ ]`. Use `Note::markdown()` for native output. [Rust document model](src/note.rs) · [Loro text and marks](https://www.loro.dev/docs/tutorial/text)
4. **Preserve position.** Parser ranges are UTF-8 byte offsets and the native model uses Loro’s byte-indexed mark and edit APIs. The WebAssembly boundary converts marker positions to the UTF-16 units used by CodeMirror. Peer selections use Loro cursors, and undo belongs to the local author. [Boundary conversion](src/browser.rs) · [LoroText positions](https://docs.rs/loro/1.18.0/loro/struct.LoroText.html)

The interaction follows SilverBullet’s live preview. A writer can read a typeset paragraph, put the caret into it, and edit its punctuation. Tables keep their grid during cell entry. Each cell maps to a range in the pipe source, so a single keystroke can update another writer’s view without rebuilding the focused input. The column widths stay steady during typing. **Edit Markdown pipes** and **Source** give direct access to the delimiters. Peer presence marks the active cell and leaves local focus alone. [SilverBullet live preview](https://github.com/silverbulletmd/silverbullet/blob/main/docs/Live%20Preview.md) · [GFM tables](https://github.github.com/gfm/#tables-extension-)

## Editing interaction review

Dioxus Native and Loro can support this editor. The weak point in the first prototype was selection ownership. A table rail could receive a click without placing a caret, a heading could receive Enter without splitting, and a local input could select only its own piece of the note. A directed Markdown text selection and a rectangular table selection give the pointer, keyboard and clipboard a shared editing model. This is the same design principle CodeMirror uses for document state, selection and transactions. [CodeMirror editor state](https://github.com/codemirror/state/blob/main/src/state.ts)

| Gesture | Expected result and implementation |
| --- | --- |
| Click or drag | Native inputs handle clicks on their letters, word selection and IME. The paper resolves its gutters to the nearest shaped caret. The right table rail belongs to the visible cell in its row and the bottom rail to the cell above the pointer. Only the button activates growth. [Native caret after a rail click](mockup/table-caret.png) · [Native pointer handling](src/native/pointer.rs) |
| Select and replace | A selection has a fixed anchor and a moving head in the Markdown. Shift+arrows, Shift+click, drag, Select All, copy, cut and replacement can cross headings, prose and table cells. Dragging within one grid selects cells by row and column. Copy writes their tab-separated values. A text selection crossing into prose includes the intervening Markdown. Parley paints the selected text in the native fields. [Selection projection](src/native/selection.rs) |
| Navigate and join | Up and Down follow the rendered lines and keep the caret in view. Horizontal arrows cross field boundaries. Enter splits any heading at the caret. At its end, Enter writes one Markdown newline and places the caret on the new line. Backspace at the start of the following paragraph rejoins it. Tab from the note title jumps to the existing body. [Navigation](src/native/navigation.rs) · [Document commands](src/native/commands.rs) |
| Toggle syntax | The drawn checkbox toggles on click. Clicking its visible bracket text places a caret. Space and X toggle inside, and F2 edits the literal characters. Heading and inline punctuation use the same source positions before and after reveal. |
| Undo | Native undo items capture both selection ends as Loro cursors. Undo after a replacement can restore the original directed selection in Live or Source. Structural edits and rectangular pastes each make one commit. [Loro undo integration](src/note.rs) |

Live uses multiple native text inputs. Split provides a baseline with one native input for the same document. Compare both on dragging beyond the viewport, marked-text composition with a real IME, and selection announcements through VoiceOver before choosing a default. The automated suite covers native IME events, a long 2× viewport, Unicode, CRLF, escaped pipes and backward selections. Native two-window editing and typing latency on large tables remain unverified.

Run `cargo test --locked --features native` for the Rust input and storage tests. Run `npm --prefix mockup test` for browser model tests. With Chrome installed, `npm --prefix mockup run build` followed by `npm --prefix mockup run test:browser` drives real pointer gestures, selection, typing and undo. It also checks that a second writer can change a heading while the first edits a cell.

## Native architecture

| Layer | Implementation |
| --- | --- |
| Interface | Dioxus Native with Blitz owns the title, prose fields, grid cells, and Source view. Live selections map to UTF-8 offsets in Loro. The browser mockup uses CodeMirror 6. |
| Shared note | Rust and JavaScript use Loro 1.18, the same text container name, and the same checkbox attribute. A snapshot containing an inline checked box and emoji was opened and edited in Rust, then read back in JavaScript with both checkbox values intact. The Rust tests also exercise disconnected peers and duplicate updates. |
| Editing surface | Each standalone ATX heading receives prefix edits at its first letter. Parley’s glyph positions locate checkboxes and Markdown styling without changing line wraps. Top-level GFM tables have stable cell inputs and byte ranges for their values, padding, and delimiters. Nested or incomplete table syntax stays editable in prose. A structural command commits its source edits together. [Native text styling](src/native/markdown.rs) · [Table source model](src/table.rs) |
| Files and sync | Persist Loro snapshots and an update journal beside the workspace. Materialize ordinary Markdown with atomic writes. Exchange missing operations on join and reconnect using Loro version vectors. |
| Inline agent | Keep the prompt and proposed diff private until acceptance. Resolve relative positions and compare the original passage before committing one undoable edit. |

The native study pins Dioxus main at `0a7242a` with Blitz `0.3.0-beta.4`. This revision applies DOM mutations after Dioxus finishes rendering, so a component can access the native editor from an effect to restore its selection. When updating the pin, run `cargo test --locked --features native` to exercise pointer, keyboard, and text input across the two views. [Pinned Dioxus renderer](https://github.com/DioxusLabs/dioxus/tree/0a7242a2a72b08975584bf8ecb05076a5ee0b9c7/packages/native) · [Upstream mutation handling change](https://github.com/DioxusLabs/dioxus/pull/5943)

## Build order

1. **Prove native typing on one file.** Open a real `.md`, edit a wrapped paragraph, select across lines, paste, undo, and save it. Start on macOS. Exercise accented input, emoji, marked IME text, arrow navigation, and selection near soft wraps. Inspect the platform accessibility tree. Confirm the native surface can return caret and range geometry for decorations. If the stock input cannot expose these, prototype a custom text surface before porting the notebook shell. A read–save round trip should preserve untouched bytes, including line endings and the final newline.
2. **Extend native lists and tables.** The native editor supports list continuation, indentation, cell navigation, adding rows and columns, and rectangular paste. Port the browser’s row and column move actions, then exercise native cell focus during incoming edits. Measure key-to-paint latency on a 100-row table with two writers.
3. **Connect two native editors.** Apply local input immediately, persist incremental edits, and exchange Loro updates and version vectors on join or reconnect. Use per-author undo and expiring peer presence. Verify identical Markdown after concurrent same-position inserts, disconnected edits, reordered and repeated updates, and an application restart. Exercise adding a column while a peer types and removing the cell that holds a peer’s caret. Apply an external file change against the last saved version. If it overlaps unsaved local edits, retain both versions for review. [Loro synchronization and undo](https://docs.rs/loro/1.18.0/loro/struct.UndoManager.html)
4. **Port the inline review with the fake agent.** Support questions, an exact replacement, and checklist conversion. Run three two-writer cases. An edit before the target moves the proposal with its text. An edit inside the target marks it stale. Undoing an accepted proposal preserves the other writer’s changes. A model provider can later implement the same proposal interface.

The next native milestone is opening and saving a real Markdown file with the same editing surface.
